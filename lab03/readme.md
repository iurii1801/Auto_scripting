# Лабораторная работа №3: Настройка планировщика задач (cron)

## Цель работы

Научиться конфигурировать планировщик задач (cron) для автоматического запуска скриптов.

## Подготовка

Работа опирается на лабораторную №2. Скопировать файлы из лабораторной №2 в новую папку `lab03` для дальнейшей работы.

---

## Задание

В рамках лабораторной работы необходимо:

1. В проекте создать ветку `lab03`. Создать директорию `lab03` и скопировать туда файлы из `lab02`.

2. В lab03 создать файл `cronjob` с задачами `cron` для запуска `currency_exchange_rate.py`:

   - Ежедневно в **06:00** — курс **MDL→EUR** за вчера.
   - Еженедельно по **пятницам в 17:00** — курс **MDL→USD** за прошлую неделю.
  
3. В `lab03` создать `Dockerfile` (на базе Ubuntu или официального Python-образа), который:

   - Установит зависимости для работы скрипта (cron, Python и нужные библиотеки).
   - Скопирует `currency_exchange_rate.py`, файл `cronjob` и `entrypoint`-скрипт в контейнер.
   - Настроит cron на выполнение задач из `cronjob`.
   - Запустит cron в фоне при старте контейнера.
   - Направит вывод задач cron в `/var/log/cron.log`.

4. Подготовить файл readme.md, в котором описать:

   - установку зависимостей;
   - примеры запуска скрипта;
   - описание структуры кода.

### Структура проекта

```bash
lab03/
├─ app/                         # код сервиса 
├─ data/                        # результаты — JSON-файлы курсов валют
│
├─ .env                         # переменные окружения (API_URL, API_KEY, пути и т.д.)
├─ cronjob                      # расписание задач cron (ежедневная и еженедельная)
├─ currency_exchange_rate.py    # основной Python-скрипт (из lab02)
├─ docker-compose.yaml          # запуск сервиса
├─ Dockerfile                   # сборка образа (Python + cron)
├─ entrypoint.sh                # настройка cron и запуск при старте контейнера
├─ error.log                    # лог ошибок скрипта (создаётся при ошибках)
├─ readme.md                    # отчёт по лабораторной №3
└─ requirements.txt             # зависимости Python (requests и др.)
```

### Краткая структура скрипта (основные функции и логика)

- **Парсинг аргументов** (`argparse`): принимает параметры `FROM`, `TO`, `DATE` и ключевые слова `yesterday` или `last_week`, а также опции `--url`, `--api-key`, `--list-currencies`.
- **Обработка специальных дат**:

  - `yesterday` — автоматически вычисляет дату предыдущего дня.
  - `last_week` — определяет диапазон дат за предыдущую неделю и выбирает среднее значение курса.
  
- **Загрузка API-ключа**: по приоритету — сначала из аргумента `--api-key`, затем из переменной окружения `API_KEY`, и, если не найден, из файла `.env`.
- **Функция `list_currencies()`**: выполняет запрос к API и выводит список доступных валют.
- **Функция `fetch_rate()`**: обращается к API с параметрами `from`, `to`, `date` (или диапазоном дат) и получает актуальный курс валют.
- **Логирование ошибок**: все исключения (сетевые, HTTP, ошибки формата или API) записываются в файл `error.log`.
- **Сохранение результатов**: результат успешного запроса сохраняется в виде JSON-файла по пути `data/rate_<FROM>_<TO>_<DATE>.json` с читаемым форматированием (UTF-8, отступы 2 пробела).
- **Поддержка cron**: скрипт полностью автономен и может вызываться планировщиком `cron`, автоматически подставляя нужные даты.

### Шаг 2. Настройка файла `cronjob`

Файл **`cronjob`** содержит расписание задач, которые автоматически запускают Python-скрипт **`currency_exchange_rate.py`** внутри контейнера.

Основные задания:

```bash
# Ежедневно в 06:00 — курс MDL→EUR за предыдущий день
0 6 * * * python3 /app/currency_exchange_rate.py MDL EUR yesterday >> /var/log/cron.log 2>&1

# Еженедельно (пятница 17:00) — курс MDL→USD за предыдущую неделю
0 17 * * 5 python3 /app/currency_exchange_rate.py MDL USD last_week >> /var/log/cron.log 2>&1
```

**Пояснение:**

- `0 6 * * *` — выполнение каждый день в 06:00 утра.
- `0 17 * * 5` — выполнение каждый **пятничный** день в 17:00.
- Аргументы `yesterday` и `last_week` обрабатываются скриптом для вычисления нужных дат.
- `>> /var/log/cron.log 2>&1` — сохраняет вывод и ошибки в лог `/var/log/cron.log`.

Таким образом, `cronjob` обеспечивает регулярное и полностью автоматическое выполнение скрипта по расписанию.

### Шаг 3. Создание скрипта запуска `entrypoint.sh`

![image](https://i.imgur.com/YY0QUxK.png)

Файл **`entrypoint.sh`** выполняется при старте контейнера и настраивает работу планировщика **cron**.
Его задача — подготовить среду, зарегистрировать расписание задач и запустить cron в активном режиме.

Основные шаги:

1. **Создание лог-файла** `/var/log/cron.log` — чтобы сохранять результаты выполнения заданий.
2. **Экспорт переменных окружения** (`env > /etc/environment`) — чтобы cron имел доступ к `API_KEY`, `API_URL` и другим настройкам.
3. **Установка расписания** (`crontab /app/cronjob`) — добавляет задания из файла `cronjob`.
4. **Мониторинг логов** (`tail -f /var/log/cron.log &`) — вывод логов в консоль в реальном времени.
5. **Запуск cron** (`cron -f`) — запускает планировщик как основной процесс контейнера, чтобы он оставался активным.

Таким образом, `entrypoint.sh` автоматически готовит среду, подключает cron и обеспечивает непрерывную работу контейнера с логированием.

### Шаг 4. Создание файла Dockerfile

![image](https://i.imgur.com/p5jei1O.png)

**`Dockerfile`** описывает процесс сборки контейнера, в котором работает планировщик **cron** и Python-скрипт.
В качестве базового образа используется **`python:3.11-slim`** — лёгкий вариант с предустановленным интерпретатором.

Основные этапы сборки:

1. **Установка пакетов** `cron`, `tzdata` — для планировщика и корректного часового пояса.
2. **Копирование проекта** в `/app` и установка зависимостей из `requirements.txt`.
3. **Добавление файлов** `currency_exchange_rate.py`, `cronjob`, `entrypoint.sh` и назначение прав на выполнение.
4. **Регистрация cron-заданий** через `crontab /app/cronjob`.
5. **Создание лог-файла** `/var/log/cron.log` для хранения результатов.
6. **Определение точки входа** `ENTRYPOINT ["/entrypoint.sh"]`, чтобы при запуске контейнера автоматически запускался cron.

Таким образом, `Dockerfile` создаёт полностью готовую среду для автоматического выполнения Python-скрипта по расписанию.

### Шаг 5. Файл `docker-compose.yml`

![image](https://i.imgur.com/dHRa0Rx.png)

Файл **`docker-compose.yml`** управляет сборкой и запуском контейнера с планировщиком **cron**.
Он использует созданный `Dockerfile` и задаёт все необходимые параметры для работы проекта.

Основные элементы:

1. **`build: .`** — указывает, что образ собирается из текущей директории.
2. **`container_name: lab03-cron`** — задаёт понятное имя контейнера.
3. **`env_file: .env`** — подключает переменные окружения (например, `API_KEY`, `API_BASE_URL`).
4. **`volumes:`** — монтирует папку `./data` на `/app/data` для сохранения JSON-файлов на хосте.
5. **`restart: unless-stopped`** — обеспечивает автозапуск контейнера после перезапуска системы или Docker.

Таким образом, `docker-compose.yml` автоматизирует запуск среды: при выполнении команды
`docker compose up -d --build` создаётся и запускается контейнер, который по расписанию выполняет задачи cron.
